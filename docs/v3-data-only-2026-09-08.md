### Explicit pre-training limitations

1. Source narration is weak multi-action context, not ground truth atomic intent.
   V-Ray examples describe searching while the screenshot shows inline asset
   renaming. They remain documented source imperfections, not relabeled successes.
   Decide on quarantine or screenshot-grounded narration correction before SFT.
2. Recorded printable input includes CAD shortcut keys and dimension input while
   the viewport has focus (e.g. Revit Space, AutoCAD `c`, SketchUp `2660`). The current
   harness clipboard-first `type_text` is not equivalent to these keystrokes.
   Establish replay parity before policy training/rollouts. The active user desktop
   was not restarted or modified by this data task.
3. Very small left drags can be click jitter. Exact source endpoints are retained,
   but native application effects were not replay-verified.
4. p-d5 lacks validation/test project families; V-Ray lacks test families. Project
   isolation is preserved rather than leaking related artifacts into those splits.
5. FreeCAD/OpenSCAD are transfer targets, absent from the ten supervised source apps.
   Their native-geometry task success must be evaluated later; no transfer claim yet.

## Full job

Service: `cadpilot-v3-data-only.service` (systemd user service).

The orchestrator is `scripts/v3_data_only.py`, separate from `full_run_chain.sh`.
Four workers cover the complete frozen 597-workflow plan, with **no workflow sample,
action cap, or window cap**. Builder recipe remains `action-aligned-v3.2`, code SHA256
`21501eb30a910727455164cd5dfcac4e601aa2bd97e8ceaba237057428abc9d5`.
Do not edit `scripts/rebuild_v3.py` or `src/cad1000/*.py` during this immutable run.

Resource limits: eight CPU equivalents, 7 GiB memory high / 8 GiB hard limit,
no cgroup swap, low CPU/I/O priority. The builder checks an 80 GiB free-disk reserve
plus its source-download headroom before each workflow.

Outputs:

- `data/shards-v3`: new accepted rows, pre-action JPEGs, trajectory windows, manifests.
- `data/raw-v3-full-cache`: dedicated source download cache. Only a completed and
  validated workflow's copied/downloaded events and clip are deleted. These are
  recoverable from the pinned source revision. Original shards/checkpoints/caches
  are not removed or overwritten.
- `data/processed/trajectory-v3`: immutable assembled view, created only after the
  full structural and real-processor gates pass.
- `runs/v3-data-only-20260908`: worker logs, status, final gates, and training hold.

Completed shards are reused on retries. Incomplete shard directories are moved
aside, never silently merged. A worker gets at most three attempts; an unresolved
failure stops the chain and records a failure status without training. The singleton
lock prevents overlapping chain launches. The service survives the chat closing;
it is a transient service, not an automatic reboot-start job.

After all 597 workflows finish, the chain validates frame bytes and labels,
source/trajectory parity, split isolation and full action coverage; token-plans
**every** train/validation/test window without truncation; tests actual pixels and
loss masks on stratified and longest windows; assembles into a new staging directory;
checks final split counts/checksums; publishes the new view; and **exits**.

`runs/v3-data-only-20260908/data-ready.json` is the completion artifact. It must say
`complete_stopped_before_training`; a running service or partial shard count is not
completion. The existing `runs/full-run/quality-hold.md` and the new data-only
`training-hold.md` must remain present. No training launch exists in this chain.

Early uncapped check: the first two completed workflows passed exhaustive structural
and trajectory/history parity checks (757 actions) and every-window real token planning
plus seven real-processor windows. This is a smoke check, not the final 597-workflow gate.
The next real-processor check covered all 2,643 windows / 4,656 actions from the first
four completed workflows, including a **45-step, 49,986-token** window and multi-window
text history. No exclusions, dropped actions, changed token plans, or loss-mask errors.
